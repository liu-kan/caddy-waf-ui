# 回溯分析

**Analysis**（`/?tab=analysis`）汇总一段时间内的 WAF 事件，找出可能的误报、可能的攻击来源、新出现的规则和高频路径，作为调整排除和策略的起点。**Overview** 页顶部的 "WAF events — last 24 hours" 是同一分析的 24 小时版本。

分析只看审计到的事件，不代表全部请求；每次最多分析最新的 2,000 条匹配事件。结论是启发式的，所有调整仍需人工确认、预览后再应用。

## 选择范围

| 选项 | 说明 |
| --- | --- |
| Storage | 本地保留的事件，或 Grafana Cloud Loki。配置了 Loki 时，超过 24 小时的范围默认查云端 |
| Site | 全部站点或单个站点 |
| Range | 最近 1 小时、24 小时、7 天（默认）、14 天、30 天 |

## 页面内容

| 区块 | 内容 |
| --- | --- |
| 指标 | 事件数与来源 IP 数；拦截数与"将拦截"数（DetectionOnly）；低于阈值的事件数（调优模式下才有）；疑似攻击者数与误报候选数 |
| Daily events | 最近 14 天每天的事件数，按拦截、将拦截、低于阈值分色。数据来自每日汇总（`/ui-data/rollups/`），原始事件过期后仍保留。只在使用本地数据时显示 |
| False-positive candidates | 误报候选，见下文 |
| Rules | 每条检测规则的事件数、拦截/将拦截/低于阈值分布、来源数（其中疑似攻击者数）、最常见的路径和变量。判定和控制类规则不列出。标有 **FP?** 的规则整体上像误报 |
| Likely attackers | 疑似攻击来源及判定原因 |
| Top sources | 事件最多的 10 个来源 IP，及其拦截数和命中的攻击类别 |
| Top paths | 事件最多的 10 个路径，及来源数和命中最多的 5 条规则 |
| New rules | 在所选范围的最后 24 小时内首次出现的规则，用于发现新的攻击手法或上线后新出现的误报 |

若有事件按命中重算的分值与 Coraza 报告的总分不一致（链式规则或自定义分值），页面底部会提示这些事件的估算只是近似值。

## 判定规则

**误报候选**：同一站点、同一规则、同一路径、同一变量，被至少 3 个不同来源命中，且其中至少 80% 的来源不是疑似攻击者。不可排除的规则（判定、初始化等）不列入。排序时，真正造成拦截的候选在前，其次按来源数、事件数。

**疑似攻击者**：一个来源 IP 满足任一条件即标记：

| 条件 | 页面上的原因 |
| --- | --- |
| 命中扫描器特征（913xxx，`reputation-scanner` 类别） | security scanner signature |
| 检测规则命中了至少 3 个不同攻击类别（如 sqli、xss、lfi） | matched N attack categories |
| 用受限文件类规则（930130、930140、920500、920440）探测了至少 5 个不同路径 | probed N restricted files or extensions |

这些阈值是固定的。一个被很多人正常使用的接口，被单个扫描器打过也不会掉出候选，因为 80% 的来源仍然"干净"；反过来，只有一两个来源触发的规则不会成为候选，需要从事件详情入手。

## 从候选到排除

1. 在 **False-positive candidates** 中点 **Review →**，打开 [规则排除](exclusions.md) 页，表单按最窄范围预填：该规则 + 精确路径 + 命中的参数。
2. 预览，查看 diff 和影响估算：会放行多少事件、来自多少来源、其中多少是疑似攻击者。
3. 疑似攻击者占比不低时缩小范围，或改为只对单个参数排除。
4. 填写原因后应用。

也可以先在事件详情里记录 "Confirmed false positive"，便于以后回看依据。判定只保存在本地，不会自动变成排除。

## 估算的局限

- 只能评估已审计的请求。未开启调优模式时，低于阈值的请求没有记录，调低阈值或提高 PL 后会新拦多少无法估出，页面会注明。
- 高于当时 PL 的规则没有执行过，提高 PL 的效果只能从"检测 PL"记录的数据里推断（见 [WAF 策略](policy.md#paranoia-等级)）。
- 命中被截断、只有规则编号没有细节、提前拦截（early blocking）的事件无法完整重放。
- 方法、Content-Type、请求体大小限制的变化会在估算中给出说明，但不能按原始请求重放。

## REST API

| 端点 | 作用 |
| --- | --- |
| `GET /api/analysis` | 参数 `range`（默认 `7d`）、`site`、`source=loki`。返回完整报告：`rules`、`fp_candidates`、`attackers`、`top_sources`、`paths`、`new_rules` 等，以及说明覆盖范围的 `coverage` |

```sh
curl -s -H "Authorization: Bearer $CADDY_UI_TOKEN" \
  "http://127.0.0.1:8080/api/analysis?range=7d&site=chat.example.com"
```
