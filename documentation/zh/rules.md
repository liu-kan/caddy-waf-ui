# 规则字典

**Rules**（`/?tab=rules`）解释后端可能记录的每个规则编号：它检查什么、属于哪个 PL、加多少分、在判定中起什么作用。事件列表和事件详情里的规则编号都链接到这里。

## 查询

搜索框可以直接粘贴：

| 输入 | 结果 |
| --- | --- |
| `930130,949110` 或 `930130 949110` | 按顺序列出这几条规则 |
| `"rule_ids_csv":"930130,949110"` | 同上，可直接粘贴事件 JSON 或 Loki 日志中的字段 |
| `93013` | 不是已知编号时按子串查找，列出 930130 等 |
| `sql`、`attack-lfi`、`lfi` | 在规则消息、类别和标签中查找，不区分大小写 |

列表形式查询时，不认识的编号会单独列出并标为 Unknown，提示去查事件的规则集版本或自定义规则，不会被静默忽略。

**Kind** 按规则类型筛选：

| 类型 | 含义 | 数量（CRS 4.25.0） |
| --- | --- | --- |
| Detection | 命中时加异常分，可以排除 | 341 |
| Decision | 比较总分与阈值并做出拦截判定：949110、949111（入站），959100、959101（出站） | 4 |
| Direct block | 不看分值直接拦截：Coraza 基础配置中的 200002（请求体解析失败）、200003（multipart 校验失败），以及 CRS 配置错误时的 901001、901500 | 4 |
| Control flow | 初始化、按 PL 跳过等流程控制 | 269 |
| Correlation | 请求结束后汇总记录 | 13 |

## 字典内容

| 来源 | 内容 |
| --- | --- |
| 内置字典 | 从后端镜像实际使用的 coraza-coreruleset 生成（当前 4.25.0），附上游 coreruleset 的规则注释和源码链接；连同 Coraza 推荐基础配置中的规则共 631 条 |
| 中文说明 | 132 条常见规则有逐条说明，22 个类别各有一段说明；没有逐条说明的检测规则显示所属类别的说明 |
| UI 生成的规则 | 9000001–9000999 路径/到期排除，9001000–9001005 策略，9001100 调优，9001200 源站探测，9002000–9002499 IP 群组拦截与试运行，9002500–9002999 IP 群组引擎与阈值调整 |
| 自定义规则 | 启动时解析 `CADDY_UI_WAF_BEFORE_FILE` 和 `CADDY_UI_WAF_AFTER_FILE` 中的规则，用其 `msg` 和标签解释 |
| 挂载的规则目录 | 设置 `CADDY_UI_CRS_RULES_DIR` 后，用该目录的规则覆盖内置字典，用于后端 CRS 版本不同的情况 |

自定义规则文件在启动时读取，修改后需重启 UI 才会更新解释。

后端 CRS 版本与字典不一致时，**Events**、**Analysis** 页顶部的状态行和事件详情都会提示。更新字典的方法见 [后端镜像](backend-image.md#升级-coraza-或-crs-时)。

## 单条规则

点编号或访问 `/?tab=rules&id=930130` 打开详情：

- **标题行**：类型、类别、PL、严重级别、分值（入站或出站）、执行阶段。
- **Explanation (Chinese)**：逐条中文说明和类别说明。
- **Definition**：检查的变量、操作符、链式条件、动作、标签、所在文件和行号；**CRS description** 是上游规则文件中的注释原文。
- **Last 14 days**：本地事件中该规则的命中次数、来源数、其中疑似攻击者数量，首次和最近出现时间，拦截/将拦截/低于阈值的分布，命中最多的路径和变量，涉及的站点。被判为疑似误报时会注明原因。
- **Events with this rule**：跳到事件列表，筛选最近 14 天含该规则的事件；**Rule source**：上游源码对应行。

不在字典中的编号会显示 "Not part of the CRS 4.25.0 dictionary"：通常是 before/after 文件中的自定义规则，或者来自其他 CRS 版本。

## 读懂一个事件的规则组合

| 组合 | 解读 |
| --- | --- |
| `930130,949110` | 930130 访问 `.env`、`.git/` 等受限文件 +5 分，949110 判定入站总分达到阈值 5 |
| `942100,949110` | libinjection 识别出 SQL 注入特征 +5 分后判定拦截。检查命中的参数是否是富文本、代码片段等正常业务内容 |
| `913100,949110` | User-Agent 是已知安全扫描器（+5 分），基本可判定为扫描行为 |
| 只有 `920350` | Host 头是纯 IP 地址，只加 3 分，低于阈值 5，事件为 DETECTED（开启调优模式，或响应状态为 4xx/5xx 时才会记录）。多见于按 IP 直接访问的扫描或健康检查 |
| 只有 detection、没有 949110 | 总分低于阈值。调优模式下，或上游返回 4xx/5xx 时才会记录 |
| 200002 单独出现 | 请求体解析失败，直接返回 400，与阈值无关 |

判定规则（949110 等）不能排除：排除它等于让这个站点的入站检查失去拦截能力。应排除的是加分的那条检测规则，而且范围越窄越好，见 [规则排除](exclusions.md)。

## REST API

| 端点 | 作用 |
| --- | --- |
| `GET /api/rules?q=930130,949110` | 查询规则，`kind` 可选。返回 `{"crs_version":"4.25.0","rules":[…]}` |
| `GET /api/rules/{id}` | 单条规则及 `note_zh`、`category_zh`、`excludable` |

```sh
curl -s -H "Authorization: Bearer $CADDY_UI_TOKEN" \
  --get --data-urlencode 'q=930130,949110' http://127.0.0.1:8080/api/rules
```
